# wb-parser-playwright

Парсер каталога **Wildberries** на **Playwright** (реальный Chromium) с обходом
антибот-защиты **JVO1 VM**. Результат сохраняется в Excel (`.xlsx`).

> Предыдущая версия на чистом `requests` лежит рядом в папке `wb-parser/`.
> Она проще, но WB отдаёт ей HTTP 403 — поэтому здесь Playwright.

---

## 1. Что делает парсер

1. Запускает Chromium (с окном, если не указан `--headless`).
2. Навешивает `stealth_sync` + патчи fingerprint (`navigator.webdriver`,
   WebGL, canvas, `chrome.runtime`, permissions, languages).
3. Открывает `wildberries.ru`, имитирует человека: движения мыши, скролл, паузы.
4. Вводит запрос в поисковую строку и ждёт выдачу.
5. **Перехватывает сетевой ответ** `search.wb.ru/.../search` — оттуда берутся все
   10 полей товара. Это основной путь: он не зависит от вёрстки карточек.
6. Если сеть не дала данных — собирает товары из DOM (резервный `page.evaluate`).
7. Дедуплицирует по `id` и сохраняет XLSX в `output/`.

## 2. Установка

```bash
python -m venv .venv

# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate

pip install -r requirements.txt

# ОБЯЗАТЕЛЬНО: скачать сам браузер Chromium (~150 МБ)
playwright install chromium
```

На Linux-сервере без GUI дополнительно нужны системные библиотеки:

```bash
playwright install --with-deps chromium
```

> `playwright install chromium` — шаг, который чаще всего забывают.
> Без него будет ошибка `Executable doesn't exist at ...chromium-xxxx/...`.

## 3. Запуск

```bash
# Базовый случай (с окном браузера)
python parser.py --query "iphone 15"

# 5 страниц + свой файл + без окна
python parser.py --query "кроссовки" --pages 5 --output sneakers.xlsx --headless

# Через прокси с авторизацией
python parser.py --query "iphone 15" --proxy http://user:pass@1.2.3.4:8080

# Диагностика: подробный лог + замедление действий для наблюдения
python parser.py --query "iphone 15" --verbose --slow-mo 300
```

### Аргументы

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `--query`, `-q` | — (обязательный) | Поисковый запрос |
| `--output`, `-o` | `wb_result.xlsx` | Имя файла; голое имя → `./output/` |
| `--pages`, `-p` | `1` | Сколько страниц обойти (~100 товаров на страницу) |
| `--proxy` | нет | `http://user:pass@host:port` |
| `--headless` | выкл. | Запуск без окна браузера |
| `--verbose`, `-v` | выкл. | DEBUG-логи |
| `--delay-min` / `--delay-max` | `1.5` / `4.0` | Пауза между страницами, сек |
| `--retries` | `3` | Попыток на страницу (пауза между ними 5 с) |
| `--timeout` | `45000` | Таймаут ожиданий Playwright, мс |
| `--slow-mo` | `0` | Замедление действий, мс — для отладки |
| `--dest` | `-1257786` | Регион (Москва `-1257786`, СПб `-102281`) |

## 4. Какие поля собираются

| # | Поле в XLSX | Источник |
|---|---|---|
| 1 | Название | `name` |
| 2 | Цена со скидкой, ₽ | `salePriceU` / 100 |
| 3 | Цена без скидки, ₽ | `priceU` / 100 |
| 4 | Скидка, % | `sale` (при отсутствии считается из цен) |
| 5 | Рейтинг | `rating` |
| 6 | Отзывы | `feedbacks` |
| 7 | ID товара | `id` |
| 8 | Ссылка | `https://www.wildberries.ru/catalog/{id}/detail.aspx` |
| 9 | Продавец | `supplier` |
| 10 | Бренд | `brand` |

## 5. Как устроен обход JVO1 VM

| Приём | Где в коде |
|---|---|
| Реальный браузер выполняет challenge-JS и ставит cookie с токеном `u` | весь скрипт |
| `stealth_sync(page)` сразу после создания страницы | `_apply_stealth()` |
| Патчи fingerprint до навигации (`add_init_script`) | `STEALTH_INIT_SCRIPT` |
| `--disable-blink-features=AutomationControlled` | `start()` |
| Реальный UA Chrome 130/131 + `ru-RU`, `Europe/Moscow`, гео Москва | `start()` |
| Пауза 5 с после загрузки — время на прохождение челленджа | `goto_search()` |
| Случайные паузы 1.5–4.0 с, скролл, ввод по символам, движения мыши | `human_*`, `goto_search()` |
| Перехват ответа `search.wb.ru` вместо парсинга DOM | `_on_response()` |

## 7. Ограничения

- **Rate limit WB.** Паузы `random.uniform(1.5, 4.0)` между страницами, пауза 5 с
  между ретраями, пауза 20 с при HTTP 429. Частые запросы приведут к бану IP.
- **Прокси** — опционально и единственный надёжный способ обойти бан по IP.
  Формат: `http://user:pass@host:port`. Работают и без логина: `http://1.2.3.4:8080`.
- **Headless заметнее.** `--headless` проще, но детектится легче (новые headless-режимы
  Chrome частично снимают этот признак). Для регулярного сбора надёжнее запуск с окном
  на отдельном профиле/машине.
- **Без API-ключей.** Используется публичный поиск, seller-API не нужен.
- **Синхронный API.** `sync_playwright`, без asyncio.
- **~100 товаров на страницу** — ограничение WB.
- **Headed требует дисплея.** Без окна (SSH, CI, контейнер, WSL без X) Chromium
  не может открыть страницу — используйте `--headless`.
- **Продавец (`supplier`) всегда пустой в DOM-пути** — в текущей вёрстке выдачи
  WB показывает бренд, но не продавца. Поле есть в JSON-ответе `search.wb.ru`;
  если перехват сети заработает (нужен «чистый» IP), значение подставится
  автоматически — [`extract_products()`](wb-parser-playwright/parser.py:414)
  уже читает `supplier`.
- Логи: консоль + `parser.log` (ротация 2 МБ × 3).

### Как читать код

| Путь сбора данных | Надёжность | Когда используется |
|---|---|---|
| Перехват `search.wb.ru` (JSON) | точная, все поля | WB не отдаёт антибот-токен |
| DOM-фолбэк (`parse_card_text`) | хорошая, 8 из 10 полей | основной путь при блокировке |

### Если WB изменит разметку

| Что искать | Где в коде |
|---|---|
| Поле поиска | `SEARCH_INPUT_SELECTORS` |
| Кнопка отправки | `SUBMIT_SELECTORS` |
| Карточки товаров (DOM-фолбэк) | `CARD_SELECTORS` |
| Регулярки разбора карточки | `parse_card_text()` |
| Структура JSON ответа | `extract_products()` |
| Признаки блокировки в DOM | `BLOCK_MARKERS` |
| Экран проверки браузера | `CHALLENGE_MARKERS` |

Как найти новый селектор: открыть сайт → `F12` → `Ctrl+Shift+C` → кликнуть по
элементу → скопировать CSS-селектор. Эндпоинт искать так: `Network` → `Fetch/XHR` →
запрос `search.wb.ru/.../search` → `Response` (его перехватчик подхватит сам,
жёстко в коде адрес не зашит).

## 8. Коды возврата

| Код | Значение |
|---|---|
| `0` | Успех |
| `1` | Ничего не найдено / ошибка сохранения |
| `2` | Неверные аргументы |
| `3` | WB заблокировал доступ (403/498) — скриншот и HTML в `output/` |
| `4` | Ошибка Playwright (чаще всего не установлен Chromium) |
| `130` | Прервано пользователем (Ctrl+C) |

## 9. Что делать, если 403 не проходит

Сначала определите, ЧТО именно блокирует. Парсер при каждом отказе сохраняет
скриншот и HTML в `output/` — откройте их и посмотрите, что показал WB.

| Симптом в логе | Что это | Решение |
|---|---|---|
| `HTTP 403 <- .../create-token`, скриншот «Возможно, нужно выключить VPN» | WB не доверяет вашему IP (дата-центр, VPN, агентский IP) | Сменить IP: мобильный интернет, VPN, другой провайдер. **Это не проблема кода** |
| Тот же скриншот, но IP домашний | IP в бане после частых запросов | Подождать 15–30 минут, не запускать сбор чаще |
| `Страница почти пустая (354 симв.)` + текст «Проверяем браузер» | Не завершился JVO1-челлендж | Увеличить `--timeout`, убрать `--headless`, не использовать `--slow-mo 0` на медленном ПК |
| `Playwright: Executable doesn't exist` | Браузер не установлен | `playwright install chromium` |
| `Page.goto: Timeout` в headed-режиме | Нет интерактивного дисплея | Добавить `--headless` |
| 0 товаров, но страница открылась | Сменилась вёрстка | Обновить `CARD_SELECTORS` и регулярки в `parse_card_text()` |

**Проверить свой IP вручную:** откройте <https://www.wildberries.ru/> в обычном
браузере. Если видите «Возможно, нужно выключить VPN» — парсер не поможет,
нужен другой IP. Если сайт открывается, а парсер нет — дело в настройках,
смотрите таблицу выше.

**Важно про WB:** ограничение по IP жёсткое. Никакие stealth-патчи его не снимают,
потому что проверяется адрес подключения, а не поведение. Stealth решает другую
задачу — прячет автоматизацию, когда IP в порядке, но WB всё равно подозревает робота.

### Повышение надёжности на «чистом» IP

1. Убрать `--headless` — headless детектится легче.
2. Не запускать сбор чаще, чем раз в несколько минут.
3. Один прогон = один запрос на страницу; пагинация медленнее, но честнее.
4. Держать паузы `--delay-min 2 --delay-max 5`.
5. Для регулярного сбора — арендовать резидентный IP у провайдера.
